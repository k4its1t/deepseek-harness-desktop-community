# DeepSeek Harness Desktop v0.3.1

> 🍎 这一版专门收拾 macOS 的“已损坏”迷惑提示：把应用签名从半成品补成结构完整、CI 可验的状态。大肥鱼这次不仅换了脸，还把证件夹整理好了 ( •̀ ω •́ )✧。

DeepSeek Harness Desktop 是面向 macOS 与 Windows 的非官方开源桌面包装。它在原生 Electron 窗口中运行 DeepSeek Harness Web UI 与 Agent 运行时，自动复用现有 `~/.dsh` 数据，普通用户无需另装 Node.js 或 `dsh`。

## 🍎 macOS 完整性修复

v0.3.0 的 DMG 本身下载与 SHA-256 都正常，但 `.app` 只保留了 Electron 主可执行文件的链接器 ad-hoc 签名。Info.plist 没有绑定、资源没有密封，严格验证会返回 `code has no resources but signature indicates they must be present`。浏览器下载又会附加 quarantine，Gatekeeper 因而可能给出笼统的“应用已损坏”提示。

v0.3.1 做了这些修复：

- 由 electron-builder 在所有打包修改完成后执行完整递归签名。
- 签名覆盖主程序、Electron Helper、Framework、原生模块、Info.plist 和全部资源。
- 无 Apple 证书时明确使用 ad-hoc 签名，不再留下半完整的链接器签名。
- 打包副本把 npm `.bin` 相对符号链接展开为普通文件，满足 Apple 严格 Bundle 规则。
- 针对 32,000+ 个运行时文件使用低文件描述符占用的顺序扫描，避免签名阶段出现 `EMFILE`。
- CI 在发布前执行 `codesign --verify --deep --strict --verbose=2`；任何内部组件或资源签名异常都会让构建失败。

## ⚠️ ad-hoc 不等于 Apple 公证

当前公开构建没有使用付费 Apple Developer Program 的 Developer ID 证书，也没有提交 Apple 公证。ad-hoc 签名能验证 Bundle 结构与内容完整性，但不能证明发布者身份。因此：

- macOS 首次启动仍可能提示无法验证开发者。
- 可以在 Finder 中右键应用选择“打开”，或前往“系统设置 → 隐私与安全性 → 仍要打开”。
- 真正做到联网下载后直接双击、无额外安全提示，需要维护者配置 Developer ID 与 Apple 公证。
- 详细步骤参见 `docs/MACOS_SIGNING.md`。不画饼，能做到哪就写到哪 (￣▽￣)b。

## 🧩 仍然包含的 3 个配套 Skill

- `/diagnose-harness-desktop`：只读检查启动、Web UI、API、会话、Profile、工具、权限与打包问题。
- `/prepare-harness-bug-report`：将诊断证据脱敏整理成可复现的 GitHub Issue 草稿，不会未经许可直接提交。
- `/analyze-images-locally`：通过用户已安装的 Ollama 视觉模型观察图片，再把结构化结果交给纯文本 DeepSeek 模型分析；支持 Tesseract 纯 OCR 降级。

前两个 Skill 随客户端内置；三个 Skill 同时提供独立 ZIP。未经明确同意，Skill 不会读取或输出 API 密钥、发送测试请求、修改配置、提交 Issue 或下载多 GB 模型。

## 🖥️ 桌面客户端能力

- 在沙箱化 Electron 窗口中运行固定版本的官方 DeepSeek Harness Web UI 与 Agent 运行时。
- 自动复用 `~/.dsh` 中的 API 配置、会话、Profile 和工具设置。
- 只监听随机 `127.0.0.1` 回环端口，不把 Web UI 暴露到局域网。
- Renderer 开启 Chromium sandbox 与 `contextIsolation`，关闭 Node integration。
- 应用退出时关闭 Harness 子进程，减少后台残留和端口占用。
- 使用“大肥鱼”应用图标，软件显示名称为 **DeepSeek Harness Desktop**。

**English summary:** v0.3.1 replaces the incomplete linker signature in certificate-free macOS builds with a complete recursive ad-hoc signature, expands npm symlinks in the packaged runtime, adds a low-file-descriptor signing walk, and makes CI enforce strict signature verification for both Mac architectures. The public artifacts are still not Developer ID signed or Apple-notarized, so Gatekeeper may require manual approval on first launch. The release retains the desktop wrapper, three companion Skills, and the “fat whale” icon. The project was produced through a Vibe Coding workflow with Codex credited as a development contributor.
